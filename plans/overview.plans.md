## Что это

- Панель ИХС — главная панель экосистемы FD · ИХС · RUSFAS: источник истины по специалистам, курсам и запускам, клиникам и слотам, позже — слушателям, документам и удостоверениям; сайты — витрины (facts 2026-11-03, 2026-11-17).
- Репозиторий `garunovm/ss-panel`, папка `surgeryschool\panel\` (`repo\`, `private\`, `archive\`), как `footdoctor\crm\` (2026-11-19).
- Стек — как Task CRM FD: Laravel, PHP 8.5, Docker + Traefik, сервер ИХС на FirstVDS (facts 2026-11-03).
- Медицинские данные не храним — только контакты и время (facts 2026-11-03).

## Поддомены и роли (2026-11-19)

Одно приложение Laravel и одна база; разделы — на разных поддоменах (у каждого свои маршруты, вход,
cookie сессии и правила доступа в Traefik).

| Поддомен (пример) | Для кого | Что там |
|---|---|---|
| `admin.*` | админ, менеджер, позже учебная часть и секретарь | всё: специалисты, клиники, курсы, записи, учётные записи, очередь на подтверждение |
| `doctor.*` | врач, ассистент | своя карточка, слоты по клиникам, записи к себе |
| `api.*` | сайты ИХС, FD, RF | обмен — [api.plans.md](api.plans.md) |
| `clinic.*` (позже) | клиники | свои записи и слоты — когда появится кабинет клиники |

- **Один репозиторий, разделы — внутренние папки** (решение пользователя 2026-11-19): `app/Admin`, `app/Doctor`, `app/Api`, позже `app/Clinic`, общее — `app/Domain` (модели и логика специалистов, клиник, слотов, записей). Для масштаба на сервере каждый раздел может работать в своём контейнере из того же кода (например, `api.*` в нескольких копиях); три отдельных репозитория не делаем. Раздел, выросший в отдельный продукт (панель клиник), можно вынести позже.
- Вид панели: каркас TailAdmin, как у Task CRM FD (боковое меню, шапка, карточки), цвета ИХС; раздел виден по акценту — `admin.*` янтарный, `doctor.*` синий — `mockups/` (2026-11-19).
- Роли: **админ** (всё, учётные записи), **менеджер** (справочники, подтверждения), **врач** (своя карточка и слоты), **ассистент** (слоты и записи своих врачей). Подробнее — [specialists.plans.md](specialists.plans.md).
- Домен: поддомены `surgeryschool.ru` (имена — уточнить при создании сервера); тест — на `hmtest.ru`.

## Решения

- Карточка специалиста и учётная запись — разные сущности; админ заводит учётку и привязывает к карточке; врач правит свою карточку и видит, где она публикуется (ИХС / FD / RF) — [specialists.plans.md](specialists.plans.md) (2026-11-19).
- Правки опубликованных данных с `doctor.*` (карточка, новая клиника) идут в очередь на подтверждение менеджеру; менеджер в `admin.*` правит сразу — [specialists.plans.md](specialists.plans.md) (2026-11-19).
- Справочник клиник — единый для экосистемы, ведёт менеджер; слоты — у врача по клиникам, ставит ассистент сам, без подтверждения; с кабинетом клиники логику расширим — [clinics.plans.md](clinics.plans.md) (2026-11-19).
- Колл-центр не меняем: заявка на приём с сайта по-прежнему уходит на его почту; панель параллельно хранит заявку и занятый слот — [clinics.plans.md](clinics.plans.md) (2026-11-19).
- Доступы: врач видит и правит только свою карточку и только разрешённые админом поля, в техническую часть не попадает; админ правит технику и схему карточки (добавляет свойства); правила проверяются на сервере и тестами — [access.plans.md](access.plans.md) (2026-11-19).
- API видит только данные для обмена: отдельный пользователь MySQL с правами только на таблицы обмена; списки участников, документы и всё остальное закрыты — [access.plans.md](access.plans.md) (2026-11-19).
- WebSocket — только в `admin.*`, для совместной работы нескольких сотрудников (списки ФИС ФРДО, программы, карточки специалистов): кто сейчас в записи, живые обновления, защита от затирания правок; в `doctor.*` и `api.*` не нужен (2026-11-19).
- Программа запуска считается сама: дата начала + регламент пункта (по умолчанию 15 мин, у пункта может быть свой) → время всех пунктов; порядок меняется перетаскиванием, менторы перетаскиваются на пункт из «Специалистов»; то же нужно в панели RF — `mockups/pages/admin-program.html` (решение пользователя 2026-11-19).
- API: панель — истина, сайты забирают изменения (`gmr.ecosystem`), слоты и запись — запросом в реальном времени; у каждого сайта свой ключ и права — [api.plans.md](api.plans.md) (2026-11-19).
