Что видит API

Контейнер api подключается к базе отдельным пользователем MySQL. У него права только на эти представления обмена:

ПредставлениеЧто в нёмПраво
exchange_specialistsопубликованные карточки специалистов — только поля с отметкой «на сайты» и только на сайты, где карточка публикуетсяобщий ID, ФИО, фото, роли, специальность, степень, регалии, направления, образование, сообщества, сайтыSELECT
exchange_coursesкурсы и запуски в статусе «идёт запись», «мест нет», «прошёл» и программыкурс, направление, запуск, даты, место, статус, мест свободно, цена, программа (пункты, докладчики по общему ID)SELECT
exchange_clinicsклиники и места с отметкой «показывать на сайте»название, тип, город, адрес, часыSELECT
exchange_slotsсвободные слоты врачей на ближайшие 3 месяцаврач (общий ID), клиника, дата, время, длительностьSELECT
appointments_inboxвходящие заявки на приём с сайта ИХСврач, слот, имя, телефон, сайт, время заявкиINSERT

Закрыто для API

Этих таблиц для пользователя MySQL api не существует — даже ошибка в коде API их не откроет:

  • ✕ users, roles, sessions
  • ✕ students — курсанты
  • ✕ student_documents — СНИЛС, дипломы, сканы
  • ✕ certificates — удостоверения
  • ✕ frdo_batches — выгрузки ФИС ФРДО
  • ✕ run_documents — договоры, приказы, протоколы
  • ✕ specialists — полные карточки, внутренние поля
  • ✕ audit_log — журнал
  • ✕ api_keys

Три уровня защиты

  1. База: свой пользователь MySQL, права только на представления обмена.
  2. Приложение: ключ сайта с правами; отдаётся только опубликованное на этом сайте.
  3. Сеть: только HTTPS, только с IP наших серверов, лимит запросов, каждый запрос — в журнал.
